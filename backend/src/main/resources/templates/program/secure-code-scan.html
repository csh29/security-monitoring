앱 목록
저장소를 받아(소스 업로드 앱은 올린 zip을 풀어) 시큐어코딩 규칙(행안부 SW 보안약점 기준)으로 소스를 점검합니다. 판정은 서버가 규칙과 연계 추적으로 하고, 그래도 못 정한 일부 탐지만 해당 메서드 코드를 AI로 보내 참고 판별을 받습니다(비밀값은 가림). 점검은 한 번에 하나만 실행됩니다. 결과는 코드 점검 결과 화면에서 봅니다. 소스 업로드는 앱 관리 권한이 필요합니다. 소스 폴더를 zip으로 올리거나(빌드 결과물 target·build·node_modules는 빼고), 폴더를 그대로 고르면 점검 대상 파일만 골라 zip으로 묶어 올립니다.
점검 이력 (최근 500건)

추적 규칙 초안

점검할 때 저장소의 프레임워크 장치(세션 값을 요청에 넣는 AOP 등)와 설정 파일을 읽어 연계 추적 규칙(trace-rules.yml)과 비교합니다. 판정을 엄격하게 하는 변경과 프레임워크 구조 기록은 점검 때 바로 반영하고, 판정을 느슨하게 하는 변경(세션 값으로 볼 키·로그인 정보 이름 추가 등)과 사용자 범위 키 추가는 여기서 근거를 확인한 뒤 반영합니다 — 세션 값이 아닌 키를 잘못 넣으면 실제 위험을 놓칩니다. 반영한 규칙은 모든 앱의 다음 점검부터 쓰이고, 반영·무시는 앱 관리 권한이 필요합니다. 바뀐 trace-rules.yml은 git으로 확인해 커밋하세요.
